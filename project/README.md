# The Content Desk — деплой

## Що всередині
- `src/App.jsx` — весь застосунок (той самий функціонал, що й раніше).
- `api/chat.js` — серверний проксі до Anthropic (ключ API лишається на сервері, у браузер не потрапляє).
- `api/board.js` — серверне сховище дошки (пости, коментарі, "хто що бачив") через Upstash Redis.

## Важливо: чому саме так зроблено сховище
У Claude-артефактах був `window.storage` — він працює ТІЛЬКИ всередині Claude.ai і поза ним не існує. Для реального деплою потрібне справжнє серверне сховище — я підключила **Upstash Redis** (безкоштовний тариф достатній для 7 людей).

Кожен пост зберігається **окремим полем** у Redis-хеші (`board:posts`), а не одним великим масивом. Це принципово важливо для твоєї вимоги "щоб дані не злітали при одночасній роботі":
- Якщо 2 людини одночасно редагують **різні** пости — вони НІКОЛИ не затруть одне одного (кожен запис іде в своє поле).
- Коментарі оброблюються окремим "атомарним" запитом на сервері (сервер сам читає-додає-записує), тому навіть коментар на чужий пост має мінімальний ризик конфлікту.
- Єдиний реальний (і дуже вузький) ризик: якщо 2 людини редагують **той самий** пост чи лишають коментар на ту саму мить — виграє останній запис. Це нормальна межа для інструменту на 7 людей без складної системи блокувань.

Дошка оновлюється кожні 4 секунди (як і раніше) + локальні незбережені зміни захищені від перезапису, поки не збережуться.

## Крок 1 — залити на GitHub
```bash
cd content-desk          # тека з цим README
git init
git add .
git commit -m "Initial deploy"
git branch -M main
git remote add origin <URL твого репозиторію на GitHub>
git push -u origin main
```
`.env` у гіт не потрапить (він у `.gitignore`) — це навмисно, секрети туди не кладемо.

## Крок 2 — Upstash Redis (сховище дошки)
1. Зайди на https://upstash.com, зареєструйся (можна через GitHub).
2. Створи Redis-базу (Create Database), регіон — той що ближче до Vercel-регіону (за замовчуванням підійде).
3. На сторінці бази знайди розділ **REST API** — там будуть `UPSTASH_REDIS_REST_URL` і `UPSTASH_REDIS_REST_TOKEN`. Скопіюй обидва.

## Крок 3 — Vercel
1. На https://vercel.com → **Add New Project** → підключи щойно запушений GitHub-репозиторій.
2. Vercel сам розпізнає Vite-проект (Framework Preset: Vite) — нічого змінювати не треба.
3. У **Environment Variables** додай:
   - `ANTHROPIC_API_KEY` — твій ключ з console.anthropic.com
   - `UPSTASH_REDIS_REST_URL` — з кроку 2
   - `UPSTASH_REDIS_REST_TOKEN` — з кроку 2
4. Deploy.

Після цього кожен з 7 людей заходить на URL, обирає своє ім'я на екрані входу — і працює на своїй дошці, як і раніше.

## Локальна перевірка перед деплоєм (не обов'язково)
```bash
npm install
cp .env.example .env      # і встав туди свої ключі
npm run dev                # UI на localhost, але /api/* не працюють без vercel dev
# або, якщо встановлений Vercel CLI:
vercel dev                  # піднімає і UI, і /api функції разом
```

## Якщо щось не так після деплою
- Заголовки/сторіз не генеруються → перевір `ANTHROPIC_API_KEY` у Vercel → Settings → Environment Variables, і подивись логи функції `api/chat` у Vercel Dashboard → Deployments → Functions.
- Дошка порожня / нічого не зберігається → перевір `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`, і логи `api/board`.
- Після зміни змінних середовища в Vercel — обов'язково зроби **Redeploy** (самі змінні без редеплою не підхоплюються).
